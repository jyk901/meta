# Mini NPU Simulator (3차 미션)

MAC(Multiply-Accumulate) 연산으로 Cross(+) / X 패턴을 판별하는 Python 콘솔 애플리케이션. 표준 라이브러리(`json`, `time`, `sys`, `os`)만 사용합니다 (Python 3.8+).

## 실행 방법
```bash
python main.py                          # 모드 선택: 1) 사용자 입력(3x3)  2) data.json 분석
python main.py data_error_cases.json    # 모드 2에서 다른 JSON 사용 (오류 처리 확인용)
python gen_data.py                      # data.json 재생성 (패턴 생성기 재사용)
```
- 모드 1: 필터 A, B와 패턴을 3줄씩 공백 구분으로 입력. 줄 수/개수/숫자 오류 시 안내 문구 출력 후 재입력.
- 모드 2: `main.py`와 같은 폴더의 `data.json`을 로드. 스키마/크기 불일치는 케이스 단위 FAIL로 처리하고 계속 진행.
- `data.json`: 과제 첨부 파일을 받을 수 없어 동일 규칙(`filters.size_{5,13,25}`, `patterns.size_{N}_{idx}`, `+`/`x`/`cross` 혼용 라벨)으로 직접 생성한 파일입니다. 공식 `data.json`이 있으면 같은 이름으로 교체하면 그대로 동작합니다.

## 구현 요약
- **라벨 정규화**: `normalize_label()`이 `+`, `cross` → `Cross`, `x` → `X`(대소문자·공백 무시)로 통일. expected와 filter 키 모두에 적용하고, 모든 비교·출력은 표준 라벨 기준. 알 수 없는 라벨은 해당 케이스 FAIL.
- **MAC 연산**: `mac()`이 이중 for문으로 같은 위치끼리 곱해 누적(`float` 반환). NumPy 등 미사용. `[보너스]` `mac_flat()`은 길이 N² 1차원 배열 버전.
- **동점 처리**: `abs(a-b) < 1e-9`이면 `UNDECIDED` (`judge()`).
- **성능 측정**: `time.perf_counter()`로 연산 함수 호출 구간만 10회 반복 측정 후 평균(ms). 파일/콘솔 I/O 제외.
- **보너스**: 모드 2 출력 끝에 2D vs 1D MAC 전/후 비교표 출력(동일 입력·동일 200회 반복, 결과 일치 assert). `make_cross(n)`, `make_x(n)` 패턴 생성기를 성능 분석과 `gen_data.py`에서 재사용.

## 결과 리포트

### 실행 결과 (기본 data.json, 12케이스)

| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
|---|---|---|
| 3×3 | 0.002 | 9 |
| 5×5 | 0.003 | 25 |
| 13×13 | 0.014 | 169 |
| 25×25 | 0.045 | 625 |

(시간은 실행 환경에 따라 달라지며 위는 한 번의 측정값입니다.)

### 실패 원인 분석
1. 기본 `data.json`은 FAIL이 0건입니다. 이유는 (a) expected `+`/`x`와 filter 키 `cross`/`x`가 정규화로 `Cross`/`X`에 통일되어 라벨 표기 차이(`+` vs `Cross`)가 오판정으로 이어지지 않았고, (b) 모든 패턴 크기가 해당 `size_N` 필터와 일치했으며, (c) 정수 0/1 입력이라 점수 차이(예: 9 vs 1)가 epsilon보다 훨씬 커서 동점이 발생하지 않았기 때문입니다.
2. 실패 진단은 `데이터/스키마 문제` → `로직 문제` → `수치 비교 문제` 순으로 분리합니다. `data_error_cases.json`으로 각각을 재현할 수 있습니다.
3. **데이터/스키마 문제**: `size_5_9`(5×5 필터에 3×3 입력 → 크기 불일치), `size_7_1`(size_7 필터 없음), `size_5_10`(expected `?` → 알 수 없는 라벨). 예외로 종료되지 않고 케이스 단위 FAIL + 사유 출력 후 계속 진행합니다.
4. **로직 문제**: 라벨 정규화를 빠뜨리면 expected `+`와 판정 `Cross`가 문자열로 달라 PASS인데도 FAIL이 됩니다. 비교를 항상 표준 라벨로 수행해 방지했습니다.
5. **수치 비교 문제**: 부동소수점은 `0.1+0.2 != 0.3`처럼 사실상 같은 값도 다르게 나올 수 있어 `==`/`>`만으로는 판정이 흔들립니다. `data_error_cases.json`의 `size_13_9`는 두 점수가 같아 `UNDECIDED`가 되고 expected `X`와 달라 FAIL로 처리됩니다. 이는 오류가 아니라 정의된 동점 정책의 결과입니다.
6. 따라서 epsilon 정책(1e-9)은 "미세한 오차는 같은 값으로 보고, 의미 있는 차이만 승패로 인정"하기 위해 필요합니다. 값이 너무 크면 진짜 차이를 동점으로 오판하므로 1e-9 정도로 작게 둡니다.

### 시간 복잡도 분석
7. `mac()`은 N×N 이중 반복으로 곱셈+덧셈을 N²번 수행하므로 입력 크기 N에 대해 **O(N²)** 입니다 (연산 횟수 열: 9 → 25 → 169 → 625).
8. 측정 시간도 N²에 따라 증가합니다. 3×3(9회) 대비 25×25(625회)는 연산 횟수가 약 69배이지만 측정 시간은 약 20~25배 정도입니다. 이는 3×3처럼 작은 입력에서는 함수 호출·루프 설정·타이머 해상도 같은 고정 비용 비중이 커서 시간이 연산 횟수에 정확히 비례해 보이지 않기 때문입니다. N이 커질수록 N² 항이 지배적이 되어 비례에 가까워집니다.
9. 13×13(169회) → 25×25(625회)는 연산 횟수 약 3.7배, 시간 약 3배로 O(N²) 추세와 일치합니다.
10. 한 쌍(패턴, 필터)당 비용이 N²이고 Cross·X 두 필터를 비교하면 2N²이며, 상수배라 복잡도는 여전히 O(N²)입니다.
11. 실제 AI의 수백×수백 필터와 수천 개 필터를 반복하면 MAC 횟수가 급격히 늘어나므로, 서로 독립적인 MAC를 동시에 처리하는 병렬 하드웨어(NPU)가 필요한 이유가 됩니다.
12. 보너스인 1차원 배열(`mac_flat`)은 `[i][j]` 이중 인덱싱을 단일 인덱스로 줄이지만, 연산 횟수는 그대로 N²이므로 복잡도는 바뀌지 않고 상수 계수만 줄어듭니다.

### 최적화(1차원 배열) 전/후 비교 (보너스, 한 번의 측정값)
| 크기 | 2D(ms) | 1D(ms) | 향상 |
|---|---|---|---|
| 3×3 | 0.0006 | 0.0004 | 1.54x |
| 5×5 | 0.0016 | 0.0010 | 1.67x |
| 13×13 | 0.0085 | 0.0061 | 1.39x |
| 25×25 | 0.0297 | 0.0240 | 1.24x |

13. 1차원 방식이 일관되게 약 1.2~1.7배 빠르지만(이중 인덱싱 제거), 크기가 커져도 N²에 비례해 증가하므로 복잡도는 O(N²)로 동일합니다.
