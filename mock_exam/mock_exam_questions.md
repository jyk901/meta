## 정답 및 해설

### Python 기초

**1. 정답: str (문자열)**

`input()`은 무엇을 입력하든 항상 **문자열(str)** 을 돌려줍니다.  
숫자로 쓰려면 `int(age)`로 변환해야 하고, 변환에 실패하면 `ValueError`가 납니다. (미션의 '숫자 변환 실패 시 재입력' 요구와 연결)  
참고: int=정수, str=문자열, bool=참/거짓, list=순서 있는 목록, dict=키-값 쌍.  

**2. 정답: dict (딕셔너리)**

**dict**는 키로 값을 찾는 자료형입니다. `state.json`의 구조(`"quizzes"`, `"best_score"` 같은 키)가 바로 dict입니다.  
**list**는 순서가 있는 목록(`quizzes`의 퀴즈 여러 개)이고, 인덱스(0, 1, 2…)로 접근합니다.  

**3. 정답: return**

**매개변수**는 함수로 들어가는 입력, **반환값(`return`)** 은 함수가 돌려주는 출력입니다.  
`print()`는 화면에 보여 줄 뿐 값을 돌려주지 않습니다. `return`이 없으면 함수는 `None`을 돌려줍니다.  

### 클래스·객체

**4. 정답: __init__ (생성자)**

`Quiz("문제", [...], 2)`처럼 객체를 만드는 순간 **`__init__`** 이 자동 실행되어 `self.question = question` 같은 초기 설정을 합니다.  
클래스는 **설계도**, 객체는 그 설계도로 만든 실물입니다.  

**5. 정답: self**

**`self`** 는 '지금 이 객체'입니다. `self.question`은 '내 문제'라는 뜻입니다.  
정의할 때는 `def show(self)`처럼 적지만, 호출할 때는 `q.show()`처럼 쓰고 `self`는 파이썬이 자동으로 넣어 줍니다.  
객체마다 `self`가 달라서 속성값이 서로 독립적입니다.  

**6. 정답: ① 속성(attribute), ② 메서드(method)**

**속성(attribute)** = 객체가 가진 데이터(변수), **메서드(method)** = 객체가 할 수 있는 행동(함수)입니다.  
Quiz 클래스라면 속성은 `question, choices, answer`, 메서드는 퀴즈 출력·정답 확인 등입니다.  

### 파일·JSON·예외

**7. 정답: 데이터 영속성**

**데이터 영속성**: 프로그램이 꺼져도 데이터가 남아 있는 성질입니다. 변수는 종료하면 사라지지만 **파일**에 저장하면 남습니다.  
**JSON**은 dict/list 같은 구조를 텍스트로 저장하기 쉬운 형식이라 `state.json`에 사용합니다. (읽기 `json.load`, 쓰기 `json.dump`)  

**8. 정답: try/except**

`try:` 안에서 오류가 날 수 있는 코드를 실행하고, 오류가 나면 `except:`로 넘어가 처리합니다.  
미션 요구: 파일이 없으면 기본 퀴즈 데이터 사용, 손상되었으면 안내 메시지 후 기본 데이터로 복구.  

**9. 정답: ValueError**

**`ValueError`** 입니다. 메뉴 입력 처리에서 `except ValueError:`로 잡아 안내 메시지를 출력하고 재입력받습니다.  
함께 알아둘 것: Ctrl+C → `KeyboardInterrupt`, 입력 스트림 종료 → `EOFError`. (잘못된 JSON은 `json.JSONDecodeError`이고 이것도 `ValueError`의 하위 예외)  

### Git ① 기록 흐름

**10. 정답: git add**

**`git add`** : 변경 파일을 스테이징(커밋 대기) 영역에 올립니다.  
흐름: 작업 폴더 → `add` → 스테이징 → `commit` → 로컬 저장소 → `push` → 원격 저장소(GitHub)  

**11. 정답: git commit**

**`git commit -m "Feat: 퀴즈 출제 기능 구현"`** : 변경 이력을 하나의 기록(스냅샷)으로 남깁니다.  
권장 메시지 형식은 `Feat:`, `Fix:`, `Docs:`, `Refactor:`처럼 작업 내용을 드러내는 것입니다. (최소 10개 이상의 의미 있는 커밋)  

**12. 정답: git push**

**`git push`** : 로컬 커밋을 원격 저장소로 업로드합니다.  
반대로 원격의 변경을 가져오는 것은 `git pull`입니다. (`git init`은 저장소를 새로 시작하는 명령)  

### Git ② 브랜치·원격

**13. 정답: git checkout (최신 Git에서는 git switch도 사용)**

**`git checkout 브랜치명`** 은 이동, **`git checkout -b 브랜치명`** 은 새로 만들면서 이동입니다.  
미션 요구: `main` 외에 추가 브랜치를 만들어 작업한 뒤 `main`으로 병합.  

**14. 정답: git merge**

`git checkout main` 으로 main으로 이동한 뒤 **`git merge 작업브랜치`** 로 합칩니다.  
미션 요구: 최소 1회 이상 브랜치 생성 및 병합(checkout, merge) 기록.  

**15. 정답: ① git clone, ② git pull**

**`git clone 주소`** : 원격 저장소를 통째로 복제(처음 1회). **`git pull`** : 원격의 최신 변경을 가져와 로컬에 반영(fetch + merge).  
13단계 실습: 별도 폴더에 `clone` → 수정 → `commit`·`push` → 원래 폴더에서 `pull`로 확인.  

### 과제 규칙

**16. 정답: question, choices, answer**

**question(문제), choices(선택지), answer(정답)**. 선택지는 4개가 기본이고, 정답은 1~4 중 하나의 번호로 관리하는 방식을 권장합니다.  
클래스는 최소 2개(예: Quiz, QuizGame). QuizGame은 퀴즈 목록·최고 점수 등을 관리하고 메뉴·풀기·추가·목록·점수·저장/불러오기 메서드를 가집니다.  

**17. 정답: state.json (UTF-8 인코딩 권장)**

**`state.json`** : 최소 스키마는 `quizzes`(퀴즈 목록)와 `best_score`(최고 점수)입니다. UTF-8 인코딩을 권장합니다.  
파일이 없으면(첫 실행) 기본 퀴즈 데이터를 사용하고, 손상되면 안내 후 복구합니다.  

**18. 정답: git log --oneline --graph**

**`git log --oneline --graph`** : 커밋을 한 줄씩, 브랜치 병합 흐름을 그래프로 보여 줍니다.  
제출물: GitHub 저장소 URL, 개발 환경 스크린샷, 프로그램 실행 결과 스크린샷(추가·목록·플레이·점수), 위 `git log` 스크린샷.
