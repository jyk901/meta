# LLM 지식 베이스 — 스키마 (Claude가 매번 먼저 읽는 규칙)

Andrej Karpathy의 "LLM Wiki" 패턴(https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)을 이 폴더에 적용한 것입니다.
사람은 자료를 모으고 질문하고, Claude는 위키를 쓰고 관리합니다.

## 구조
- `raw/` — 원본 자료(기사, 논문, 메모, 데이터). **읽기 전용: 절대 수정·삭제하지 않는다.** 이미지는 `raw/assets/`.
- `wiki/` — Claude가 전부 작성·유지하는 마크다운 위키.
  - `index.md` — 모든 페이지 목록(링크 + 한 줄 요약). 질문에 답할 때 **가장 먼저** 읽는다.
  - `log.md` — 시간순, 추가만 하는 작업 기록.
  - `sources/` — 원본 1개당 요약 페이지 1개.
  - `entities/` — 사람, 조직, 제품, 장소 등.
  - `concepts/` — 개념, 아이디어, 주제.
  - `analyses/` — 질문에 대한 답변, 비교, 종합 정리.
- `tools/search.py` — 위키 키워드 검색: `python3 tools/search.py <검색어>`

## 페이지 형식
- 파일명: 소문자-케밥-케이스 `.md` (한글 제목이면 한글 파일명 허용).
- 맨 위에 YAML 프런트매터:
  ```yaml
  ---
  title: 페이지 제목
  type: source | entity | concept | analysis
  sources: [raw/파일명]       # 근거가 된 원본
  updated: YYYY-MM-DD
  ---
  ```
- 다른 페이지 링크는 Obsidian 위키링크 `[[페이지명]]`.
- 사실 주장에는 근거 출처(`sources/...` 페이지)를 밝힌다. 출처 간 모순은 지우지 말고 "⚠️ 상충" 으로 표시.

## 작업 1: Ingest (자료 넣기) — "raw/xxx 를 ingest 해줘"
1. 원본을 읽는다(이미지는 텍스트를 먼저 읽고 따로 본다).
2. 핵심 내용을 사용자와 짧게 이야기한다.
3. `wiki/sources/`에 요약 페이지를 만든다.
4. 관련 `entities/`, `concepts/` 페이지를 새로 만들거나 갱신한다(자료 하나가 10~15쪽을 건드릴 수 있음).
5. `index.md`를 갱신한다.
6. `log.md`에 `## [YYYY-MM-DD] ingest | 제목` 형식으로 추가한다.
기본은 한 번에 한 자료씩. 사용자가 원하면 일괄 처리.

## 작업 2: Query (질문하기)
1. `index.md` → 관련 페이지 → 필요하면 `tools/search.py` 순으로 찾는다.
2. 근거를 인용하며 답한다(표, 차트, Marp 슬라이드 등 형식 자유).
3. 가치 있는 답은 `wiki/analyses/`에 새 페이지로 저장하고 index·log 갱신.
4. log: `## [YYYY-MM-DD] query | 질문 요약`

## 작업 3: Lint (점검) — "위키 점검해줘"
모순, 새 자료로 낡은 주장, 들어오는 링크가 없는 고아 페이지, 언급만 되고 페이지가 없는 개념,
빠진 상호 링크, 웹 검색으로 메울 수 있는 빈칸을 찾아 보고하고 고친다.
log: `## [YYYY-MM-DD] lint | 요약`

## 규칙
- 이 스키마는 사용자와 함께 고쳐 나간다. 규칙을 바꾸면 이 파일도 갱신한다.
- 위키는 git으로 버전 관리된다. 큰 작업 후에는 커밋을 제안한다.
